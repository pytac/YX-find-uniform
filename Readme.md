# 衣寻 - 找到你的衣服

## 介绍

这个系统是一个基于 `微信小程序` (用户前端) 和 `flask` (后端)，用于寻找丢失的衣服（特别是校服）。

## 项目规划

- service: 后端
- - school: 学校相关接口
- - service: 服务相关接口
- user: 用户端
- - user: 普通用户界面
- - maker: 制造商界面
- - agent: 供 AI Agent 查看校服消息的 skill 文档

## Agent 支持（查看校服消息）

`user/agent/SKILL.md` 是一份给 AI Agent 用的操作手册，描述「怎么查某个账号的校服和消息」
这一整套流程：探活 → 查名下校服 → 按学校逐个拉消息 → 合并成人话，以及领取、上报丢失两个写操作。

有了它，Agent 可以直接回答这类问题，用户不用自己在小程序里翻：

- 「我有哪些校服？」
- 「我有没有丢了还没领的校服？」
- 「我 002 学号那件校服有人捡到吗？」
- 「帮我把这件标记成已领回。」

使用前提只有两个参数：

| 参数 | 获取方式 |
|---|---|
| 服务器地址 | 部署时确定，默认 `http://<服务器IP>:5000` |
| UID | 小程序「设置 → 用户UID → 复制」 |

文档里包含了完整的接口契约（请求体 / 返回结构）、消息 `type` 定义、
服务端英文短语与中文说法的对照表，以及多校服、跨学校场景必须遵守的三条规则，
按它写脚本或接进任意 MCP 客户端都可以。

> 注意：`uid` 由手机本地生成，Agent 无法自行推算，必须由用户提供。

## 缺陷

这部分是这个项目的缺陷，因为**时间限制**，所以没有做， 所以**不可直接投入生产环境使用**

- 验证用户身份，避免“你不是人类”
- 密码使用明文存储，不安全，需要哈希加盐处理
- 数据库使用json文件，会有锁的冲突，占用内存大，容易保存不了数据。这里需要改成 SQL 数据库

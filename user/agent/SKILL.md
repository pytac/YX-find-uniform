# 衣寻 · 查看校服消息

给 Agent 用的操作手册：如何一步一步从接口里拿到某个账号的校服和消息，并把结果讲给人听。
本文件只描述流程和接口契约，不绑定具体实现——用 MCP 工具、HTTP 客户端还是脚本都行。

## 一、先确认两个参数

| 参数 | 从哪来 | 说明 |
|---|---|---|
| `server_url` | 部署时确定，默认 `http://<服务器 IP>:5000` | 总服务器，负责校服归属与学校路由 |
| `uid` | 小程序「设置」页显示的用户 UID | UUID v4 形式，如 `9849a008-2b53-4108-9216-a7e2dc5f7e46` |

两者缺一不可。`uid` 是**手机本地生成**的，Agent 无法自己推算，必须由用户提供；
如果用户说「我不知道 UID」，让他打开小程序 → 设置 → 用户UID → 点「复制」。

## 二、体系结构（必须理解，否则会查漏）

```
           ┌────────────────────────────┐
   uid ──► │ 总服务器 :5000              │  校服归属、学校路由
           │ /user/uniforms             │
           └──────────┬─────────────────┘
                      │ 每件校服带 school_service
        ┌─────────────┴──────────────┐
        ▼                            ▼
┌───────────────────┐        ┌───────────────────┐
│ 学校 A :8888      │        │ 学校 B :8888      │
│ /user/get_msg     │        │ /user/get_msg     │
└───────────────────┘        └───────────────────┘
```

三条硬规则：

1. **消息不在总服务器上**，只存在各自学校的服务器里，必须逐个学校去问。
2. **一个 uid 可以有多套校服，还可能分属不同学校**。所以绝不能「取第一个学校地址」就完事，
   那会漏掉另一所学校的全部消息。
3. 同一个学校下的多件校服**共用一份消息列表**（消息按 `uid` 存储），按学校去重即可，不用按 YID 重复查。

## 三、标准流程

### 第 1 步 · 探活（可选但建议）

```
POST {server_url}/maker/check_sid
{"sid": "__probe__"}
→ 200 {"Phrase":"Check sid success","Status":true,"Detail":{"res":false}}
```

能拿到 JSON 就说明服务器在线。连不上时直接告我「服务器没开或地址不对」，不要继续往下查。

### 第 2 步 · 查名下校服

```
POST {server_url}/user/uniforms
{"uid": "<UID>"}

→ 200 {
    "Status": true,
    "Detail": {
      "uniforms": [
        {"yid":"...", "student":"20240101", "sid":"Example",
         "school_name":"示例中学", "school_service":"http://192.168.2.128:8888"}
      ]
    }
  }
```

这一步同时给出了后面要用的**学校服务器地址**。`uniforms` 为空 = 这个账号还没绑过校服。

### 第 3 步 · 逐校拉消息并合并

对第 2 步结果里的每个**不重复的** `school_service` 各发一次：

```
POST {school_service}/user/get_msg
{"uid": "<UID>"}

→ 200 {
    "Status": true,
    "Detail": {
      "msg": {
        "1730012345": {"type":1, "time":1730012345, "auto_delete":false,
                       "detail":{"yid":"...", "name":"示例中学"}}
      }
    }
  }
```

把各校结果并成一张表，每条补上 `school_name`、`school_url`、`key`（`msg` 的键）三个来源字段，
再按 `time` 倒序排。**`key` 是字符串，别转成数字**，它是后面领取时要用的参数。

`type` 含义：

| type | 含义 | 能不能领取 |
|---|---|---|
| 1 | 丢失通知 | ✅ 还没领取 |
| 2 | 领取 / 绑定通知 | ❌ 已经领过了 |
| 3 | 激活通知 | ❌ |
| 4 | 学校删除通知 | ❌ |

### 第 4 步 · 组装成人话

推荐输出顺序：**UID → 名下校服清单 → 待领取的丢失通知 → 其他消息 → 查询失败的学校**。

待领取的每一条都要把领取所需的四个参数一起列出来，人才能直接照着操作：

```
待领取的丢失通知：1 条
  · 2026-10-26 21:03　示例中学　YID：a1b2c3d4-...
    领取参数 → uid=...　yid=...　key=1730012345　学校=http://192.168.2.128:8888
```

## 四、两个写操作

### 领取丢失（= 衣服找回来了）

```
POST {school_service}/user/get_loss
{"uid":"<UID>", "yid":"<该通知里的 yid>", "key":"<该通知的 key>"}
```

`key` 必须来自第 3 步，且 `yid` 必须和那条通知里的 `yid` 完全一致，否则服务端会拒绝（返回
`yid is not belong to key`）。成功后这条通知会从列表消失，并新增一条 type=2 的领取通知。
**这是写操作，执行前必须让用户确认一次。**

### 上报丢失

```
POST {server_url}/user/loss
{"yid":"<YID>"}
```

走总服务器，由它转发给对应学校。仅当校服已绑定（`is_active`）时可用；用户只是「看看」的时候别调。

## 五、失败短语对照表

服务端返回的 `Phrase` 是英文，**不要原样念给用户**，按这张表翻译：

| Phrase | 真实含义 | 该怎么说 |
|---|---|---|
| `key not found` | 这条消息已被领取 / 被删除 | 这条丢失记录已经失效，回首页刷新一下，列表里没有就说明处理完了 |
| `key is not loss information` | 不是丢失通知 | 这条消息不是丢失记录，没法领取 |
| `yid is not belong to key` | 扫到的校服和这条记录对不上 | 扫到的校服和这条丢失记录不是同一件，请重新扫描 |
| `yid is not belong to uid` | 校服不归这个账号 | 这件校服不属于当前账号，换个账号或找学校核实 |
| `yid not found` | 校服编号不存在 | 没找到这件校服，请核对 YID |
| `yid is not active` | 还没绑定 | 这件校服还没绑定，不能上报丢失 |
| `yid is already active` | 已被绑定 | 这件校服已经被绑定过了 |
| `uid not found` | 该账号在这所学校没记录 | 这个账号在该校查不到记录 |
| `school service unreachable` | 总服务器连不上学校 | 学校服务器连不上，稍后再试 |

拿不准的短语统一回「操作失败，请稍后重试」，不要暴露内部措辞。

## 六、示例

```bash
# 1) 看这个账号有哪些校服
curl -s -X POST http://192.168.2.128:5000/user/uniforms \
     -H "Content-Type: application/json" \
     -d '{"uid":"9849a008-2b53-4108-9216-a7e2dc5f7e46"}'

# 2) 按返回的 school_service 逐校查消息
curl -s -X POST http://192.168.2.128:8888/user/get_msg \
     -H "Content-Type: application/json" \
     -d '{"uid":"9849a008-2b53-4108-9216-a7e2dc5f7e46"}'
```

典型对话：

> **用户**：我 002 学号那件校服有没有人捡到？
> **Agent**：（第 2 步拿到 uid 下两件校服；按 school_service 去重后查了两所学校；
> 在示例中学查到一条 type=1 且 yid 对应学号 002 的丢失通知）
> 有一件。2026-10-26 21:03 示例中学上报了你的校服（YID a1b2c3d4…）丢失，
> 现在还没领取。要我帮你标记为已领回吗？

## 七、注意事项

- **多学校必须逐个查**，某所查失败时把该校列进「查询失败」，其他学校的结果照常输出，不要整体报错。
- **不要缓存消息结果当权威**：领取、删除都会改变列表，每次问答重新查一次最省事。
- `auto_delete=true` 的消息 15 天后由学校服务器自动清理；`type=1`（丢失通知）不自动删除。
- `uid` 是本机生成的，换手机 / 清缓存会变成新账号，此时 `/user/uniforms` 会返回空——
  这时让用户重新扫码绑定，或从旧设备截图里找回原 UID。
- 面向内部局域网 http 部署，正式上线需换成 https 域名。
